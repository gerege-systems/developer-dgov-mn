# Участие в разработке

> 🌐 [English · Монгол](CONTRIBUTING.md) · [中文](CONTRIBUTING_ZH.md) · **Русский**

Спасибо за интерес к улучшению **Government Template Platform V3.0**
(Цахим үйлчилгээг бүтээх суурь — «основа для создания цифровых услуг»)!

## Начало работы

1. Сделайте форк репозитория и создайте ветку от `main`:
   `git checkout -b feat/short-description`.
2. Поднимите стек — см. раздел «Быстрый старт» в [README](../README.md).
3. Внесите изменения в `backend/` и/или `frontend/`.

## Перед открытием PR

**Бэкенд (Go):**

```bash
cd backend
make fmt          # gofmt
make lint         # golangci-lint
make test         # юнит-тесты
make pre-push     # воспроизвести CI (lint + тесты + дрейф swag + сборка)
```

**Фронтенд (Next.js):**

```bash
cd frontend
npm run lint
npm run build
```

- Соблюдайте границы **Clean Architecture**: слои business/domain не должны
  импортировать веб-фреймворк.
- Добавляйте тесты для нового поведения. Обновляйте соответствующие документы в
  `backend/docs/` (а также версии `_MN`, `_ZH` и `_RU`).
- Если вы меняете аннотации HTTP-обработчиков, выполните `make swag`, чтобы
  `docs/` оставались в актуальном состоянии.
- Придерживайтесь существующего стиля кода и соглашения о многоязычных
  комментариях и документации.

## Сообщения коммитов

Используйте ясные сообщения в повелительном наклонении (приветствуются
Conventional Commits): `feat(auth): add passkey login`, `fix(cors): …`,
`docs: …`, `test: …`.

## Pull request

- По возможности делайте PR сфокусированными и небольшими.
- Заполняйте шаблон PR; связывайте с соответствующим issue.
- Все проверки CI должны проходить.

## Сообщения об ошибках и запросы возможностей

Создавайте issue по шаблонам из `.github/ISSUE_TEMPLATE/`. По вопросам
безопасности **не** открывайте публичный issue — см. [SECURITY.md](../SECURITY.md).
