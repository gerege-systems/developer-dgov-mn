# Gerege Template Platform V3.0

> **Основа для создания цифровых услуг** — **на базе eID · с AI** —
> готовая к продакшену основа для построения любой цифровой услуги
> государственного или частного сектора.

**Gerege Template Platform V3.0** — это *основа для цифровых услуг
государственного и частного секторов*: Go-бэкенд на Clean Architecture +
фронтенд Next.js BFF + конвейер Gemini AI, связанные вместе, усиленные по
безопасности и готовые к расширению в любую систему. Вы создаёте ценность, а не
инфраструктуру — идентификация, безопасность, AI и каркас сервисов уже решены с
первого дня. Эталонное развёртывание работает как **Gerege Template Platform** на
[template.gerege.mn](https://template.gerege.mn) и показывает единый вход через
eID в продакшене.

Платформа — это код-выражение заявленной миссии **Gerege Systems ХХК**:
*«доставлять государственные и частные услуги гражданам простым способом»*.
Одна основа несёт и услугу государственного органа, и продукт банка, страховой
компании, финтеха, больницы или школы — с одинаковым уровнем доверия.

Готовая к продакшену, усиленная по безопасности **full-stack основа**, построенная
на Clean Architecture — базовый слой для создания цифровых услуг. Она соединяет
Go-бэкенд (**chi · net/http + pgx (pgxpool) + PostgreSQL + Redis**) с фронтендом
Next.js (**BFF**), уже связанные и готовые к расширению в любую систему. Бэкенд
использует `net/http` из стандартной библиотеки с роутером
[go-chi/chi](https://github.com/go-chi/chi) и драйвером
[jackc/pgx](https://github.com/jackc/pgx) с рукописным SQL — без ORM.

## 📌 Происхождение и открытый код

**Бэкенд** является производной от открытого проекта
[snykk/go-rest-boilerplate](https://github.com/snykk/go-rest-boilerplate)
(MIT, автор Najib Fikri); мы перенесли слой HTTP с **Gin на chi (net/http)** и
слой данных с **sqlx на pgx (pgxpool, рукописный SQL)**, сохранив полный набор
возможностей. Указание авторства исходного проекта сохранено в
[AUTHORS](../AUTHORS). Этот проект распространяется по **лицензии MIT** — см.
[LICENSE](../LICENSE).

## Возможности

- **Clean Architecture** — `handler → usecase → repository → domain`, без обратных
  импортов; бизнес-ядро никогда не импортирует веб-фреймворк.
- **Аутентификация — eID + Google** — единственный способ входа: **вход через eID**
  (доверяющая сторона eID Mongolia: QR-код / мобильный deep-link / push по
  регистрационному номеру с long-poll-сессией). Рядом — привязка аккаунта
  **Google OAuth**. Сессии — JWT access + refresh (ротация); выход отзывает оба
  (refresh + список запрещённых access). Входа по паролю или email/OTP нет.
- **Профиль eID PKI** — читает личность вошедшего гражданина из IdP: связанные
  организации и уполномоченные подписанты, сертификаты, зарегистрированные
  устройства и активность.
- **Организации и членство** — создание/поиск организаций (запрос в
  государственный реестр через Gerege Verify/XYP) и управление участниками/ролями,
  изолированные по пользователям через RLS.
- **Портал государственных услуг** — гражданская поверхность
  `Төрийн үйлчилгээ`: каталог услуг, заявки, справки, уведомления, платежи, запись на приём.
- **API-шлюз** — управляемые админом сервисы / маршруты / consumers / API-ключи /
  политики с телеметрией запросов (обзор + логи).
- **Провайдер OIDC (SSO)** — платформа сама может выступать провайдером
  идентификации: собственный Go-провайдер OAuth2/OIDC ведёт потоки
  вход/согласие/выход, поэтому доверяющие стороны входят через неё
  (`Sign in with Gerege SSO` в эталонном развёртывании). Включается при заданном `OAUTH_ISSUER`.
- **Подписание документов (PAdES)** — серверное подписание PDF через eID Mongolia
  `/v3` с постоянным сертификатом Document-Signer; ретранслятор подписи позволяет
  сторонним RP подписывать через учётные данные eID платформы.
- **Сторонние интеграции** — OAuth-подключения по пользователям (Google
  Drive/Meet, Dropbox) с шифрованием токенов при хранении (AES-256-GCM), а также
  собственное SFTP-хранилище приложения **Gerege Space**.
- **AI-конвейер (Gemini)** — REST-клиент без SDK с function calling: текстовый и
  голосовой чат, речь в текст, текст в речь, синхронный перевод. Слоистый
  системный промпт (жёстко заданные ограничения + настраиваемые админом
  область/инструкции в базе) удерживает ассистента в заданной предметной области;
  инструмент `search_knowledge` опирает ответы на таблицу `ai_knowledge`.
- **Журнал аудита** — с хеш-цепочкой, только на добавление (чтение и проверка
  целостности только для админа).
- **RBAC и суперадмин** — динамические роли и каталог разрешений; модель из
  4 ролей (**суперадмин → админ → менеджер → пользователь**), где суперадмин —
  единственная роль, управляющая учётными записями администраторов.
- **Оформление сайта** — настраиваемый админом общесайтовый вид
  (акцент / шрифт / плотность / тема) для публичных страниц и переопределения по пользователям.
- **Усиление безопасности** — строгие заголовки безопасности (CSP, HSTS,
  COOP/COEP/CORP), белый список CORS, ограничение запросов, полные таймауты
  HTTP-сервера, параметризованные запросы, Row-Level Security в Postgres с
  проверкой применимости при старте. См. [SECURITY.md](../SECURITY.md).
- **Наблюдаемость** — трассировка OpenTelemetry + метрики Prometheus +
  структурированные логи Zap; `/metrics` и `/swagger` в продакшене закрыты bearer-токеном.
- **Фронтенд BFF** — браузер общается только с маршрутами Next.js своего origin,
  которые проксируют к бэкенду на стороне сервера (токены не попадают в
  клиентский JS); двойная защита от CSRF (собственный заголовок + проверка
  origin), слой данных TanStack Query.
- **Устанавливаемое PWA** — manifest + иконки + service worker на Serwist;
  кешируется ТОЛЬКО статика — все пути `/api/*`, аутентификации и eID работают
  как NetworkOnly, HTML не кешируется вовсе. Настройка:
  [frontend/README_RU.md](../frontend/README_RU.md#pwa--установка-как-приложение).
- **С тестами** — юнит-тесты и интеграционные тесты на testcontainers.

## Быстрый старт

**Требования:** Go 1.26+, Node 20+, PostgreSQL 15+, Redis 7+ (для полного стека
рекомендуется Docker).

```bash
# 1) Бэкенд  →  http://localhost:8080
cd backend
cp internal/config/.env.example internal/config/.env   # задайте JWT_SECRET (≥32 символов), БД, Redis, учётные данные EID_* RP

# 2) Фронтенд →  http://localhost:3000
cd ../frontend
cp .env.example .env.local                              # BACKEND_URL=http://localhost:8080
npm install
npm run dev
```

Или поднимите весь стек (db + redis + migrate + api + web):

```bash
docker compose up -d --build
```

Откройте **http://localhost:3000** и выберите **Вход через eID** (отсканируйте QR /
откройте мобильное приложение eID или введите регистрационный номер, чтобы
получить push). Привязка аккаунта Google появляется, когда настроены её учётные данные.

## О компании Gerege Systems ХХК

**Gerege Systems ХХК** (Гэрэгэ Системс, Улан-Батор, основана в 2017 году)
объединяет канал доставки государственных и частных услуг гражданам с
регулируемыми доверенными сервисами.

- **Миссия:** *«доставлять государственные и частные услуги гражданам простым
  способом»* — позиционирование этой платформы напрямую следует из неё.
- **Регулируемые доверенные сервисы:** одна из **пяти** организаций Монголии с
  лицензией на выдачу сертификатов электронной подписи (код лицензии `0925`,
  срок действия 2025-06-12 → 2030-06-12; см.
  [реестр](https://mddic.gov.mn/signature/) MDDIC). eID Mongolia (`e-id.mn`) —
  продукт этого направления.
- **Отрасли:** каналы государственных услуг (Gerege Kiosk, Gerege App),
  платёжная инфраструктура (Smart POS), образование (EdTech), здравоохранение
  (MedTech), страхование и банки.

> **Уточнение.** Gerege Systems **не** создавала **DAN** (национальная
> аутентификация), **XYP** (обмен данными) и **e-Mongolia** — это государственные
> системы, принадлежащие Национальному дата-центру, а Gerege выступает по
> отношению к ним доверяющей стороной / каналом. Эта платформа также находится на
> стороне *потребителя* этих систем. Её архитектура электронной подписи следует
> *модели* eIDAS, но не является **квалифицированной** доверенной услугой,
> внесённой в реестры ЕС.
