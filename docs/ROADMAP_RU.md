## ✅ Сделано

### Базовая платформа (Gerege Template Platform V3.0)

- Go-бэкенд на Clean Architecture: chi (net/http) + pgx (без ORM) + PostgreSQL + Redis
- RBAC: динамические роли/разрешения и каталог; RLS в Postgres (ENABLE+FORCE, роль приложения без суперправ)
- Наблюдаемость: трассировка OTel + Prometheus + Zap; заголовки безопасности, CORS, лимиты запросов, таймауты сервера
- Фронтенд Next.js 15 BFF: сессия в httpOnly-куках, i18n mn/en/zh/ru, TanStack Query
- CI: gofmt + vet + тесты с race + дрейф swag + lint/сборка фронтенда + gitleaks; Deploy после CI

### AI-конвейер (Gemini)

- `pkg/gemini` — REST-клиент без SDK (повторы + backoff); чат с function calling (резервный ответ на языке пользователя)
- Голос: понимание аудио (голосовые сообщения), STT, TTS (PCM→WAV), синхронный перевод
- Трёхслойный системный промпт: жёстко заданные ограничения + scope/instructions из базы; инструмент `search_knowledge` (`ai_knowledge`)
- Интерфейс админа + API (`/admin/ai/prompts`, `settings.manage`)

### Аутентификация — eID + Google + dgov SSO

- **Вход через eID Mongolia RP** стал единственным способом входа (пароли/OTP/регистрация убраны):
  QR (`/eid/start`), push по регистрационному номеру гражданина (`/eid/start-id`), long-poll-сессия (`/eid/poll`)
- **Привязка Google OAuth** — привязать аккаунт Google к пользователю eID и затем входить через него; отвязка
- **Потребитель dgov SSO (OIDC)** (`sso.gerege.mn`) — start / callback / native (мобильный PKCE) / logout
- Главная страница = экран входа через eID; исправление жёсткого редиректа
- Сессия: JWT access + refresh (ротация, защита `kind`); выход = отзыв refresh + список запрещённых access

### Профиль eID PKI

- Личность eID вошедшего гражданина: связанные организации и уполномоченные
  подписанты, сертификаты, зарегистрированные устройства, активность
  (`/me/*`, `/users/me/eid/*`)

### Организации и государственные услуги

- **Организации и членство** — создание/поиск (справка из государственного
  реестра через Gerege Verify/XYP), управление участниками/правами; защита по
  пользователям через RLS
- **Портал государственных услуг** — каталог, заявки, справки, уведомления,
  платежи, запись на приём (`/gov/*`)
- **Gerege Core find** — обёртка справок по пользователям/организациям (`/core/*`)

### DAN как провайдер OIDC (SSO issuer)

- Ядро вход/согласие/выход поверх **Ory Hydra** (`/provider/*`) — активируется только при настроенной Hydra
- Поверхность `/admin` для регистрации и управления OAuth2-клиентами RP + админские API-ключи
- Пропуск согласия для собственных клиентов; запоминание согласия (спрашивается только в первый раз)
- Передача RP claim о привязке Google (`google_sub/email/name/picture`); показ имени RP на экране входа
- Экраны `/oauth` в собственном дизайне DAN (SigninShell + LoginForm)

### API-шлюз

- CRUD сервисов / маршрутов / consumers / API-ключей / политик + обзор и логи телеметрии (`/gateway/*`)

### Подписание документов (PAdES)

- Серверное подписание PDF через eID Mongolia `/v3`; постоянный сертификат
  Document-Signer (в продакшене fail-closed)
- **Ретранслятор подписи** (`/rp/sign/*`) — сторонние RP подписывают *через*
  учётные данные RP eID платформы DAN

### Интеграции и хранилище

- OAuth-интеграции пользователя (Google Drive/Meet, Dropbox) — токены зашифрованы AES-256-GCM (`/integrations/*`)
- **Gerege Space** — собственное SFTP-хранилище приложения с квотой на пользователя (`/gspace/*`)
- Ресурсы подписи и печати (`/assets/*`)

### Безопасность, аудит, управление

- **Журнал аудита** — с хеш-цепочкой, только на добавление; чтение и проверка целостности админом (`/audit`, `/audit/verify`)
- Приём **событий безопасности** (`/security/events`)
- **RBAC и суперадмин** — модель из 4 ролей (суперадмин → админ → менеджер →
  пользователь, миграция `23`); суперадмин — единственная роль, управляющая
  администраторами (`/superadmin/*`)
- Усиление безопасности: таймауты HTTP-сервера и MaxHeaderBytes, проверка RLS при
  старте, двойная защита CSRF и валидация маршрутов в BFF, `/metrics` и
  `/swagger` в продакшене закрыты bearer-токеном

### Оформление сайта

- Настраиваемое админом общесайтовое оформление (акцент / шрифт / плотность /
  тема) на публичных страницах (`/site/appearance`)
- Разделены области действия админа (публичные страницы) и пользователя (приложение)

### Развёртывание

- Продакшен-развёртывание на [template.gerege.mn](https://template.gerege.mn)
  (docker compose: db + redis + migrate + api + web)
- Вся документация обновлена парами EN/MN; DEPLOYMENT(_MN).md, AI_PIPELINE(_MN).md, CLAUDE.md
